DeepRobotics Jueying Lite3 — Operating from a web browser

No software installation is required on the operating device (phone, tablet or laptop). The device only needs to be on the same network as the console computer: the robot's Wi-Fi (192.168.2.x) or the same LAN (192.168.1.x).

1. Requirements

  • The console computer is powered on, on the robot's Wi-Fi or on the same LAN, and the Lite3 Pilot console is running (it serves the web interface on port 8123).
  • Your device (phone/tablet/laptop) is:
    • on the robot's Wi-Fi (the hotspot from the robot's QR label), or
    • on the same LAN as the console computer.
  • No web server, no VPN, no internet access is needed — everything is local.

2. Find the console address

  1. On the console computer, the address to use is its own IP on the network that your device shares:
    • on the robot's Wi-Fi: e.g. 192.168.2.22
    • on the same LAN: e.g. 192.168.1.210
  2. Console URL format: http://<console-computer-IP>:8123
    Example: http://192.168.2.22:8123

3. Open and connect

  1. Open that URL in the browser on your device.
  2. Check the robot IP shown under Advanced → Robot IP: it must be the motion host of the network you are on:
    • robot Wi-Fi: 192.168.2.1
    • ethernet/LAN: 192.168.1.120
  3. Press 🔌 Connect. Wait for ✅ Connected (the status line also shows the ping result).
  4. The camera pane opens automatically (when the robot's camera service is running).
  5. Operating controls: 🐕 STAND / 🪑 SIT, the action buttons (dance, hello, flips…), the two joysticks (left: forward/back + turn, right: slide), STOP and E-STOP.

4. Before you move the robot

  • Clear the area (about 5 m) and keep the physical E-stop within reach — it always overrides the software.
  • The robot must be standing: driving commands are ignored while it is sitting or lying down.
  • If the header shows E-STOP latched, press ⟲ Return to re-arm. While latched, no command is sent.
  • Both joysticks are spring-centred: release = stop. Holding a position keeps driving until released.

5. Troubleshooting

  • The page does not open: your device is not on the same network as the console computer, or the IP is wrong. Re-join the robot Wi-Fi / LAN and re-check the IP.
  • Page opens but not connected: verify Advanced → Robot IP matches the network (2.1 on robot Wi-Fi, 1.120 on LAN), and that the robot is powered and awake.
  • Buttons are greyed until connected: expected. They enable automatically on connect.
  • Commands seem to do nothing: robot not standing, or software E-stop latched (press ⟲ Return). Note that UDP gives no acknowledgement — confirm motion visually.
  • No camera: the robot's camera service must be running on the robot. The console retries automatically every ~8 s.
  • No battery / IMU readout: requires a one-time setting on the robot (telemetry target in ~/jy_exe/conf/network.toml). Driving works without it.

Security note: the console is a local service without authentication — keep it on trusted, local networks and close the browser session when finished.
